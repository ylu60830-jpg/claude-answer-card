# answer-card

给 Claude Code 用的终端文本收集表单：用**原生表单**一次收多条文本，不限做题。

聊天输入框**回车即发送、打不了换行**——一次要回多个问题、或一个问题要写多行时，
多条内容挤在一条消息里很难组织。这个 MCP 服务器把多段文本拆成竖排输入框：
每个要点一个框、Tab/Enter 切换、允许留空，和选择题用的 `AskUserQuestion` 分工明确。

典型场景：方案陈述（1、2、3）、需求澄清的多个问题、做题填空、任何要用户分段回复的场合。

```
┌──────┬──────────┬──────────┬──────────┐
│ 进程 │ 到达时间 │ 服务时间 │ 完成时间 │
├──────┼──────────┼──────────┼──────────┤
│  P1  │    0     │    5     │          │
│  P2  │    1     │    3     │          │
└──────┴──────────┴──────────┴──────────┘
              ↓ 紧接着弹出
        P1 · 完成  [     ]
        P2 · 完成  [     ]
```

## 能力

| 工具 | 用途 |
|------|------|
| `ask_blanks` | 一次收集多个空。字段竖排、可上下滚动，**字段数没有上限**；每字段可带多行 `desc` 当题干 |
| `ask_pages` | 连弹多页，一次填完一整张表 |
| `ping` | 连通性检查 |

**自动宽度**：每次调用时现测终端列数，折到「列数 − 8」。

> 为什么不能直接读？Claude Code 用 `CREATE_NO_WINDOW` 起 MCP 子进程，
> 子进程拿到的是自己的隐藏控制台，恒报 120×30，窗口怎么缩都不变。
> 真正的 ConPTY 挂在 `claude.exe` 上，所以 server 沿父进程链逐个 `AttachConsole`，
> 取第一个尺寸不同的控制台。测完立刻摘下，免得被终端的 Ctrl+C 波及。
>
> ⚠️ **退化情形**：真终端恰好也是 120 列时，没有「尺寸不同的」控制台可找，
> 函数会退回自身宽度——读数看着正常，其实没验到祖先链。要确认测量真的生效，
> 把窗口拉成非 120 列再看一次。
>
> 想跳过测量：设 `ANSWER_CARD_WIDTH` 或 `COLUMNS`。两者都**原样当宽度用、不再减 8**，
> 所以设成全窗口列数会让正文贴着右边被截断。一般不设。

## 题干放哪

| 位置 | 放什么 | 硬限制 |
|------|--------|--------|
| `prompt`（卡顶） | 卡片级说明；单题且折行后 ≤4 行的题干 | 4 行，超了 server 截断 |
| 字段 `desc` | 题目级题干；多题时每题放该题**第一个**框 | 多行不折叠，超宽自动折行 |
| 聊天正文 | **材料**：表格、宽代码、长数据 | — |

- 表格别进 `prompt`/`desc`：会按终端宽度折行，对齐一折就崩。表格放正文 ` ```text ` 代码块，卡里写「见上方表 A」。
- 框数按题定：默认一题一框；一题要多条回答且条数未知时，预分配 4 个 `text` 框、允许留空。
- schema 在弹出时冻结，**没有「+ 动态加框」**；选择类问题交给 `AskUserQuestion`。

## 安装

需要：Python 3.10+、Claude Code。**uv 是可选的**——有它不用管依赖，没有也能装。

**1. 安装 skill**（可选，但强烈建议——它包含用哪张卡的判断规则）

把 `SKILL.md` 放到：

```
~/.claude/skills/answer-card/SKILL.md
```

**2. 注册 MCP 服务器**

把 `<路径>` 换成 clone 下来的目录。

**有 uv**（推荐：依赖自动拉取，不和本机环境打架）：

```bash
claude mcp add answer-card --scope user -- uv run -q --with "mcp>=2,<3" --no-project <路径>/server.py
```

**没有 uv**：先给某个解释器装上依赖，再让 Claude Code 用**同一个解释器**启动。

```bash
python -m pip install "mcp>=2,<3"
claude mcp add answer-card --scope user -- python <路径>/server.py
```

★ 第二条命令里的 `python` 必须就是装了 `mcp` 的那个。用虚拟环境更稳，写全路径：

```bash
claude mcp add answer-card --scope user -- <venv>/Scripts/python.exe <路径>/server.py
```

**3. 重启 Claude Code** 生效。

验证：

```bash
claude mcp get answer-card     # 应显示 Status: ✔ Connected
```

## 用法

装好之后不用手动调用——把 `SKILL.md` 放进 skills 目录，Claude 会按场景自己选：
要一次收多条文本时弹卡，有固定选项的选择题走 `AskUserQuestion`。也可以直接点名：

> 用答题卡把这道题的答案收一下

单独测服务器（不需要客户端）：

```bash
uv run -q --with "mcp>=2,<3" --no-project python test_client.py
```

没装 uv 也行：先 `pip install "mcp>=2,<3"`，再直接 `python test_client.py`——
脚本找不到 uv 就退回当前解释器（运行时会打印一行说明）。

## 已知限制（都是实测出来的，不是猜的）

| 限制 | 说明 |
|------|------|
| `prompt` 最多 4 行 | server 先截：保留前 3 行 + 「…（题干过长，完整题目见上方正文或字段说明）」。**长题干改放字段 `desc`** |
| `prompt` 单行超宽会截断 | 客户端对 `prompt` 每行只截断、**不重新折行**，所以 server 必须预折行；`desc` 的长行由客户端自动折行 |
| 自由字符串数组不支持 | Pydantic `list[str]` 会被客户端 `-32602 InvalidParams` 拒绝；只有多选枚举数组能渲染成折叠列表 |
| 不能动态加框 | schema 在弹出时冻结；一题多答用预分配框（条数未知给 4 个、可留空） |
| 卡片打开后缩放窗口不重排 | 内容在弹出那一刻就定死了；关掉重开即可 |
| 题干不支持 Markdown | `prompt` 和 `desc` 都是纯文本，加粗、反引号、`#` 都原样显示，别写 |
| 数字框只收小数 | `9/4` 这类分数用 `text` 类型 |

一个反直觉的结论：**正文是聊天文本、没有硬换行**，软折行由终端按窗口宽度做。
但这块长板现在只留给**材料**（表格、代码、长数据）——题干能进卡（`desc`）就别放正文，
卡和正文分开会让填写时来回翻。表格宽度记得留余量，`desc` 里只写「见上方表 A」。

## 平台

主要针对 **Windows + Windows Terminal**（宽度测量走 Win32 `AttachConsole`）。
其它平台会退回 `os.get_terminal_size()`，能用但自动宽度依赖终端是否上报列数。

## 背景

这是从一个「答案卡」需求做出来的：先做了填空表单，踩完 4 行限制、截断、宽度测量
这些坑之后，才发现和原生 `AskUserQuestion` 是两条不同的渲染架构——
一个把排版交给客户端，一个把排版压在服务器上。两边的边界写在 `SKILL.md` 里。
